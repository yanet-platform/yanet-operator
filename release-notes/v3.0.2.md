# Operator and chart 3.0.2

The operator image and Helm chart now share the same release number. Stable
release CI sets both chart `version` and `appVersion` from the released image
version before packaging. Existing chart versions remain immutable.
The chart is now published at `oci://ghcr.io/yanet-platform/charts/yanet-operator`;
the Docker image stays at `ghcr.io/yanet-platform/yanet-operator`. Distinct OCI
repositories keep their shared version tag from overwriting either artifact.

## Runtime defaults

- `YanetConfig.spec.images.tag` is inherited by every palette image with an
  omitted or empty tag. A palette tag overrides it; an installation container
  tag overrides both. Registry/prefix inheritance is unchanged.
- Runtime Pods default to wildcard `NoSchedule` and `NoExecute` tolerations.
  Deployment patches can replace or clear them. Controller Pod placement is
  still configured independently through Helm values.
- Dataplane hugepages can use the node's `status.allocatable` resources instead
  of a hardcoded count. `hugepages: {size: 2Mi}` (omitted/zero count) reserves the
  allocatable pool of that size. A positive count preserves explicit sizing.
  Omitted hugepages infer the single positive pool; multiple positive sizes
  require an explicit size. Missing selected pools fail resource preflight
  before workload changes. Node status updates refresh the reservation without
  storing a node-specific count in the shared palette. Explicit shutdown remains
  possible after a node loses its automatic hugepage pool.

## Upgrade

The Kubernetes API remains `yanet.yanet-platform.io/v1alpha1`. No CRD reset is
required for a 3.0.x installation, but apply the updated CRD schemas before
using `images.tag` or automatic hugepage counts. Helm does not upgrade CRDs in
its `crds/` directory automatically. Keep explicit counts during an upgrade if
the reservation must remain fixed, and select the intended size on nodes with
multiple hugepage pools.

BIRD socket mounts remain explicit Deployment patches. Mount a dedicated host
directory such as `/run/yanet2/bird` at the runtime's `/run/bird` path, sharing it
with the adapter/announcer. Host package cleanup of `/run/bird` then does not
remove the runtime socket. Coordinate socket ownership/path handover before
rolling live workloads.

Pre-3.0 installations still require the [3.0.0 replacement procedure](v3.0.0.md).
Unit, admission, rendering and envtest results do not establish forwarding,
hugepage provisioning or hardware recovery behavior on a target node.
