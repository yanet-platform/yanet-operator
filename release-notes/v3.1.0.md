# v3.1.0 — managed workload credentials and gateway SSH authentication

## Added

- Optional cert-manager Certificate management with explicit issuer references,
  node/installation/role-bound SPIFFE identities and per-role credential mounts.
- Durable, validated credential generations and API-independent consumer startup
  checks. Issuance, delivery and application loading remain separate contracts.
- An optional, pinned cert-manager Helm dependency; existing cluster-wide
  installations retain ownership when the dependency is disabled.
- `certificates.sshTrustBundle` for an independent OpenSSH ECDSA P-256 public CA
  bundle, persisted with gateway credentials and checked during offline startup.
- `certificates.additionalGatewayAccounts` for explicit local login grants merged
  with effective UID-bound workload accounts. Policy changes update the gateway
  startup gate and Pod template; CA-only changes preserve the leaf certificate.

## Configuration

Enable `manageCertificates` only after cert-manager CRDs and the constrained
issuer/approval policy are ready. The feature is disabled by default. Keep the
application's native TLS/authenticator configuration in its existing generator.
The operator delivers trust and policy rather than rewriting application YAML.

See [managed workload certificates](../MANAGED_CERTIFICATES.md) for the complete
schema, role isolation, two-stage bootstrap, rotation and recovery boundaries.
The optional dependency does not provision issuer keys or authorize identities.
