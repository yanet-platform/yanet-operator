## Breaking API reset

Operator **3.0.0**, Helm chart **0.2.0**, manages YANET2 through a single
`yanet.yanet-platform.io/v1alpha1` API:

| Resource | Kind | Scope |
| --- | --- | --- |
| `yanets` | `Yanet` | Namespaced |
| `yanetconfigs` | `YanetConfig` | Cluster; singleton `config` |

The former component-based `v2alpha1` implementation is now `v1alpha1`.
The legacy single-node implementation, AutoDiscovery, validators and tests
are removed. There are no compatibility aliases or conversion webhooks.
The component palette, patches, box types, native sidecars, explicit NUMA and
typed Multus network attachments retain their behavior.

The supported controlplane NUMA count is **1 through 4**, defaulting to 1 when
omitted. CRD validation, admission and runtime rendering enforce this bound before
fan-out allocation. Disabled domains retain their physical indices.

Helm values now use `yanetconfig` instead of `yanetconfigV2`. Three metrics lose
the `v2` qualifier: `yanet_deployments_created_total`,
`yanet_deployments_updated_total`, and `yanet_update_throttled_total`.
The chart contains one matching Grafana dashboard.
Legacy-only `yanetconfig_reconcile_*` and `yanet_resources_*` collectors are removed.

### Installation and replacement

The standalone `install.yaml` now includes admission/TLS wiring and requires
cert-manager v1 with its CA injector. Helm retains certgen hooks by default and
supports `webhook.certManager.enabled: true` with managed Certificate/Issuer
resources. Wait for certificate issuance and CA injection before creating custom
resources. Custom webhook ports and ServiceAccount creation/reuse are wired to
the manager and its RBAC. See [the release guide](../README_RELEASES.md).

Use a clean installation of the new CRDs and recreate the desired configuration.
Changing only an operator image or running `helm upgrade` is insufficient:
Helm does not upgrade/delete CRDs from `crds/`, and the former namespaced
`YanetConfig` CRD cannot change scope in place.

For an existing installation, export the configuration and record a rollback
procedure before removing anything. Drain all runtime consumers with the old
operator and wait for their Pods to terminate. `stop: true` is a reconciliation
freeze, not a drain. Complete deletion/finalization of the old custom resources
with their old controller before retiring it. Remove the old chart/webhook
configuration and obsolete CRDs only after confirming the drained state.
Deleting a CRD deletes all its custom resources.

Install chart 0.2.0 and recreate `YanetConfig/config` plus the namespaced `Yanet`
objects using the component-based schema. Reusing legacy `nodename`/`type` specs
is unsupported. Old `YanetV2` manifests need the new API version/kind, and old
owner references are not adopted. Verify admission, workload ownership,
NUMA/sidecar/network rendering and runtime behavior on the target cluster.

### Reconciliation and rendering fixes

- Conflicting node acquisition no longer prevents release of former nodes or an
  explicit installation drain. Foreground deletion and ownership checks remain.
- Report-only reconciliation includes retained orphans and missing/changed/foreign
  inline ConfigMaps in drift status. Prune telemetry counts successful deletion
  requests only, not observations or repeated visits to terminating resources.
- Typed NAD namespace defaults use the installation namespace, irrespective of
  patched Deployment metadata. Ordinary one-shot initializers with `op-` names
  are preserved alongside managed native sidecars.
- Automated analysis propagates tool and full envtest/race failures; fork PRs
  build without attempting image publication or privileged review comments.
