# v3.3.0 — optional Helm runtime resources

The operator image and Helm chart are both `3.3.0`. The operator code and CRD
schemas are unchanged from `3.2.0`.

## What changed

- Helm can render named `Yanet` installations in the release namespace through
  `yanets.<name>.spec`. The existing `yanetconfig.spec` still renders the
  cluster-scoped `YanetConfig/config` singleton.
- Both resource definitions accept an optional `annotations` map for deployment
  metadata supplied by the caller.
- Chart-managed runtime resources can use fail-closed validation when
  `webhook.certManager.enabled` is enabled. The `Fail` policy remains
  incompatible with chart-managed runtime resources using the certgen hooks.

## Upgrade and bootstrap

Keep existing Helm values if runtime resources are managed separately. When
moving existing objects to the chart, coordinate ownership and pruning before
changing their source. On a fresh cluster, install the operator first and
verify both webhook CA bundles and fail-closed admission before enabling the
runtime resources. Apply the singleton before installations that use its
palette. Ordering annotations alone do not establish webhook readiness.
