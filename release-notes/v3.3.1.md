# v3.3.1 — stable gateway grants for wired clients

The operator image and Helm chart are both `3.3.1`. The `Yanet` and `YanetConfig`
CRD schemas are unchanged from `3.3.0`.

## What changed

- Gateway policy includes the configured `gatewayPermissions` of client profiles
  wired into an installation's `boxType`, even when the client is disabled or
  scaled to zero. Profiles outside the box wiring do not gain grants. Client leaf
  certificate issuance and delivery still depend on workload needs.
- Toggling a client leaves the gateway Pod template unchanged when both the
  policy and the set of managed server roles stay the same. A policy change or
  removal of a workload that also serves as a managed server can still roll the
  remaining gateways.
- To revoke access, edit `gatewayPermissions` or remove the role from the box
  wiring. Disabling a client does not revoke its configured grants.

## Upgrade managed gateways

1. If coming from `v3.1.0`, first upgrade to operator/chart `3.2.0` with the
   matching `3.2.0` exporter image pinned by digest. Follow the
   [v3.2.0 upgrade procedure](https://github.com/yanet-platform/yanet-operator/blob/v3.2.0/release-notes/v3.2.0.md#before-upgrading-from-v310)
   without changing the existing gateway policy during the checkpoint handoff.
2. Before upgrading an existing managed gateway to `3.3.1`, finish any pending
   handoff on the revision-aware version that preserves the existing policy.
   Verify `activated: true` in the controller-owned `policy-state` annotation
   for each managed-gateway installation. An already activated handoff does not
   need to be repeated for this upgrade.
3. Review configured grants for disabled clients. If the previous policy omitted
   those clients, the first publication with the new renderer can load their
   configured grants and cause a one-time gateway rollout. Verify that the
   resulting policy contains only the intended grants.

See the [managed certificates runbook](https://github.com/yanet-platform/yanet-operator/blob/v3.3.1/MANAGED_CERTIFICATES.md#policy-handoff-and-upgrade-from-v310)
for details on refreshing and verifying offline checkpoints.
