# Operator improvement priorities (3.2)

This brownfield review follows the [BMad Method](https://github.com/bmad-code-org/BMAD-METHOD/tree/v6.12.4) analyst and architecture perspectives. The decisions below concern three people: the on-call engineer diagnosing a blocked upgrade, the site owner authorizing recovery, and the maintainer qualifying a release. Findings come from the reconciler, rendered artifacts and tests; there are no site measurements in this review.

| Priority | Evidence and consequence | Improvement and acceptance criterion |
| --- | --- | --- |
| First: make the next action visible | `internal/controller/yanet_conditions.go` reports issuance/delivery and update waits. `internal/controller/policy_handoff.go` separately tracks activation and the UID/revision acknowledgment in annotations. A synchronized Deployment does not tell on-call whether the site has refreshed checkpoints. | Provide a read-only policy-handoff condition with reasons for waiting for rollout, waiting for acknowledgment, and activation. Exercise absent, stale and current ACKs and a changed Node UID. The displayed state must follow the reconciler, never generate an ACK or infer checkpoint freshness. A read-only inspection recipe is included in this release. |
| First: qualify the recovery path people actually use | `internal/controller/certificate_recovery_test.go` runs the credential writer and gate against local files. `internal/manifests/validation_envtest_test.go` checks Kubernetes API acceptance. Neither starts a site's native gateway or restores its checkpoints. | For each supported image/configuration and active NUMA topology, record the image digests, Pod IP/Service transport results, allowed and denied RPCs, rotation/reconnect, and offline restore from the refreshed checkpoint. Verify ACL freshness separately. A missing or stale result blocks that site's rollout, not the existence of a build artifact. |
| Measure before optimizing node handoff | `validateExclusiveNodes` in `internal/controller/yanet_reconciler.go` reuses child inventory per namespace, but iterates installations, selected Nodes and Deployments. Complex legacy placement can legitimately delay acquisition. There is no measured latency regression here. | Benchmark disjoint installations and overlapping legacy selectors at representative fleet sizes. Record API list counts, allocation and reconcile latency. If the scans dominate, index Deployments by controller UID within one reconcile; retain live ownership reads and require the same handoff outcomes, including terminating Pods and unrelated workloads. |

Two constraints apply across all three proposals: the cluster API cannot attest to offline checkpoint replacement, and scheduling eligibility is not authority to delete a neighbor's workload. Do not trade either safeguard for a green status or a faster reconcile.
